# Changelog

## v0.15.0 — 2026-11-07

- Tride 0.15.0 writes format 0.75 (0.14.x wrote 0.74): a light or a camera is an object of the scene, a node that holds it, and keeps only its own settings; its place, turn and parent are the node's, as for any object. A file saved by this release with a light or a camera in it needs Tride 0.15.0 or later on every player; Tride 0.14.x refuses it with the "newer format" error that asks to update Tride.
- Files saved by Tride 0.14 and earlier open in the editor and on every player and are upgraded as they open: each light and camera gets an object of its own where it stood, and its keys, bindings and state values move onto that object. The editor says so under Notes on opening ("upgraded to the current format") and opens the project as changed, so saving writes the new form.
- A file in one of the early forms Tride no longer converts is now refused with a message that names the form and says what to do (open it in Tride 0.14.0 and save it, or import the model again), instead of being converted on open: manifests before version 7, and files that keep their scene, clips, skins or a morph rest only in the glTF copy, keep line loops or triangle fans, name nodes by their glTF index, or come from before the format was stamped.
- Any node can keep a rotation order: X, Y, Z (the default, as before) or H, P, B (heading about Y, then pitch about X, then bank about Z, as in Cinema 4D). Its typed angles and its angle keys turn in that order on every player and in the editor.
- A camera's view ignores the scale of its object and of every group above it, as on Android and the web: a scaled camera object no longer changes near, far and focus or skews the frame, and a tap through it lands on what is shown.
- Memory no longer grows while frames are not drawn (a long frame, a stalled GPU): animated data such as clone placements and growth pulses is uploaded once per drawn frame, the newest only. In a test with the render thread held for 3 seconds, 7 buffers were made instead of 800.
- Breaking: `TrideScene.listLights()`, `listCameras()`, `TrideLightDescriptor` and `TrideCameraDescriptor` are removed from `TrideCore`, and `TrideRecordLight` and `TrideRecordCamera` no longer carry `parent`, `translation` and `rotation`. Read lights and cameras from `sceneRecord()`: the node row whose `light` or `camera` names a record holds its place, and the record holds its settings. A light's or a camera's pose is its node's; the runtime no longer writes a pose on `/lights/...` or `/cameras/...`.
- A light or a camera is built on the object that holds it and moves, turns and hides with it like any object; hiding the object turns its light off. The runtime hands over light and lens values as drawn, so an animated spot cone or a colour keyed per channel keeps its other values, and near, far and magnification follow the same rules on every platform.
- A model whose morph weights rest away from zero keeps its other rest weights when an animation drives only one of them; before, the first write set the others to 0.
